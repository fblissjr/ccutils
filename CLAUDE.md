# Start Here

Uses uv. Run tests: `uv run pytest tests/ --confcutdir=tests`. Run the dev CLI: `uv run ccutils --help`.

Always practice TDD: write a failing test, watch it fail, then make it pass. Commit early and often; bundle test + implementation + docs per commit.

## Architecture in one paragraph

Four tiers: Claude Code JSONL -> Parquet lake (`parsers/parquet_writer.py`, re-derivable cache) -> `etl.log_entries` staging (`etl/staging.py`, cleared after every run) -> star-schema facts (`etl/*.py`, one populator per fact). Entry point: `run_v15_etl(conn, session_path, ...)` in `etl/orchestrator.py`; DDL single source of truth: `create_star_schema()` in `schemas/star/schema.py`. Batch drivers: `export/duckdb_archive.py` (duckdb + json) and the render-only html/markdown exporters. Run metadata is three grains -- `etl.batch_runs` (CLI invocation, `BatchRun` context manager) / `etl.runs` (session) / `etl.steps` (DAG node, recorded by `lineage_upsert`) -- see STAR_SCHEMA.md "Run metadata".

## Rules that exist because something shipped broken

- **Every fact populator goes through `lineage_upsert` (`etl/upsert.py`).** Pitfalls: `payload_cols` must NOT include `session_key`; target table needs `date_key`+`time_key`; aggregate facts pass `timestamp_col=`; shared tables (two populators, e.g. `fact_session_facets`) MUST pass `soft_delete_scope_sql` or one populator soft-deletes the other's rows.
- **A populator's projection MUST emit one row per its declared `natural_key`; `lineage_upsert` RAISES otherwise.** Fix the projection (see the `QUALIFY` in `_PROJECT_USES_SQL` / `_PROJECT_RESULTS_SQL`), never collapse inside the shared helper: only the populator knows which row should survive. `NATURAL_KEYS` (`schemas/star/schema.py`) is the single source of truth for table -> key, guarded by a drift test and checked by `ccutils audit`.
- **Populators reading PERMANENT facts (not staging) must scope inbound to staged sessions** (`AND session_id IN (SELECT DISTINCT session_id FROM etl.log_entries ...)`) or they rescan the whole persistent warehouse every call.
- **No migrations from the past unless the owner explicitly asks for one -- rebuild instead.** `create_star_schema` fingerprints every base table on open and raises `SchemaMismatchError` when the file differs from the current DDL (the CLI turns it into a rebuild instruction). Adding a column to a shipped table means editing its `CREATE TABLE` and nothing else. After renames, grep the `semantic_` views and the column-list assertions in `tests/test_star_schema_ddl.py`. Do not build an upgrade path: every ALTER brings back columns that write NULL forever (no DEFAULT) and predicates that are NULL-blind on old rows.
- **Closures wrapping `run_v15_etl` list every swallowed kwarg explicitly, never `**kwargs`** -- a `**_legacy_kwargs` shim once silently dropped `--private`.
- **`_PROGRESS_TABLES` (`export/duckdb_archive.py`) lists every DATA fact `run_v15_etl` populates, excluding the audit tables (`etl.runs/batch_runs/steps`).** Stale entries undercount the progress display; audit rows would inflate it.
- **The project-boundary rule lives in exactly two mirrored places**: `project_dir_sql` (`etl/utils.py`, SQL) and the walk-up loop in `parsers/discovery.py::find_all_sessions`. Never add a third copy. `tests/test_all.py::TestProjectRuleEquivalence` fails on drift, but agreement is not correctness: both copies were once wrong the same way about the workflows layout and it stayed green. Pair any two-implementation agreement check with an expected-value oracle.
- **Agent transcripts: identity comes from the FILE, and the sidecar states what the path cannot.** Every line of an agent file carries the PARENT's `sessionId` (nested agents carry the ROOT's), so never key on an embedded sessionId, including `$.sessionId` in `raw_json`. Identity is the `session_id` COLUMN, stamped at Tier 1 from the `agent-<id>` stem and re-enforced at staging load. Layout: `<project>/<parent-uuid>/subagents/agent-<id>.jsonl` plus an optional `.meta.json`; workflow agents nest under `subagents/workflows/<wf-id>/`, so never assume `subagents` is the last directory, and cut the project boundary at the `subagents` segment. Depth and parentage are NOT derivable from location or sessionId: read `spawnDepth` and `parentAgentId` from the sidecar, and check its other stated fields before writing any walk. Fixtures must use this layout and `entry_session_id` (`tests/helpers_ccutils.py::write_minimal_session`); a flat fixture once kept discovery green while it returned nothing on real data. Detail: `docs/JSONL_CONTRACT.md`.
- **Facet catalog is the single source of truth** (`etl/facets/catalog.py::FACET_SPECS`); `schemas/star` imports FROM it at DDL seed time, never the reverse (import cycle at CLI startup). `dim_facet_type` uses `CREATE TABLE IF NOT EXISTS` + `INSERT ... ON CONFLICT DO NOTHING` so historical prompt_version rows survive -- same pattern for any future history-retaining dim. Tier 2 credentials resolve only via `cli/utils.py::build_facet_extractor_or_exit`.
- **A hash guards CONTENT; anything DERIVED from content is not covered by it.** `dim_memory.content_hash` gates the whole import, so when a parser's OUTPUT contract widens, unchanged files take the no-op path and the new projection never appears. Re-derive the projection for current rows, and do NOT open a new version (the memory did not change, our reading of it did). **Verify parser changes against a warehouse that already holds the rows, never only a fresh build.**
- **A global source (not per-session) still goes through the run-metadata system.** Being outside `run_v15_etl` is a statement about GRAIN, not a licence to skip lineage. Wrap it the way `run_memory_import` does: `EtlRun.start(run_kind="global_source")`, a `run.step()` with counts derived from the work, `run.fail()` on error. Re-raise when the output is load-bearing; record and carry on when it is additive, as memory is.
- **A Type 2 dimension does NOT inherit the fact lineage block wholesale.** `dim_memory` takes `created_at`/`created_by_version_key`/`etl_run_id`/`record_source` but NOT `is_deleted`/`deleted_at` (`is_current`/`valid_to` are its deletion mechanism) and NOT `hash_diff` (`content_hash` is the change detector), and it must not go through `lineage_upsert`. Version identity is `(memory_id, version_num)`, never `(memory_id, content_hash)`: reverted content repeats its hash.
- **Key a dimension on its whole identity, not the part that looks unique in your corpus.** `dim_memory.memory_id` needs `scope + agent_scope + owner_root + owner_key + file_name`. A short key shows up as one row flip-flopping between bodies. Corpus validation cannot substitute for reasoning about the key space.
- **Ingesting an external file format: enumerate the syntaxes before writing the parser.** `bridge_memory_link.link_syntax` keeps `[[wiki]]` and `[Title](file.md)` links distinct because they resolve differently (a markdown target is a file name; a wiki target is an identifier matched on name-or-stem modulo `-`/`_`). Resolve exactly or leave `is_resolved = FALSE`; prefix or substring matching invents edges.
- **`--private` is best-effort on render formats (html/markdown), NOT a sharing guarantee, and NOT wired into the duckdb/json ETL** (loud `UsageError` there). It fails loud when cwd is unresolvable instead of no-opping -- the silent-privacy-no-op class shipped three times; never reintroduce it. Comprehensive channel-walking: `internal/plans/private_hardening.md`. **`--no-thinking` is enforced separately on EVERY surface** -- ETL (`etl/orchestrator.py`, staging cleared), markdown (`export/markdown.py`, per-block skip), HTML (`export/html.py::_strip_thinking_blocks`, filters loglines before any consumer sees them), Claude.ai import (`parsers/claude_ai.py`, filtered at parse). It shipped **ignored entirely by HTML** -- flag accepted, exit 0, output byte-identical -- while a test file named after the flag stayed green because it covered the ETL tier. Adding a render surface means wiring it again and asserting the effect. Raw `message_json` never survives staging regardless; the Parquet lake intentionally retains everything (delete post-run if unwanted).
- **An agent transcript's task prompt is an `isMeta` user entry.** Skipping isMeta is right for a parent session and drops the most descriptive line of an agent file; such agents summarise to `(no summary)` and render-format curation (`is_curated_out`) then discards them. Discovery and curation are two independent ways a transcript disappears.
- **A rare-event claim needs a sample larger than the event's inverse rate.** Scan the whole corpus (cheap for one predicate) and state the claim as a RATE with its measurement attached, not as an invariant. Claims 2 and 5 of `docs/JSONL_CONTRACT.md` both shipped as absolutes from a sample, and both were wrong.
- **A control that never ran gives no verdict, in either direction.** Before believing a mutation result, confirm the changed line is executable code and that the runner emitted a result line.
- **Exit-code-only CLI flag tests are insufficient** -- assert the flag's actual effect (sanitized paths, absent thinking), not just acceptance.
- **HTML export security is load-bearing -- do NOT remove without understanding the XSS implications.** There are TWO independent channels from untrusted transcript content to HTML and they are guarded by different things: the MARKDOWN channel (`render_markdown_text`) is safe because `_MD` runs `html=False` and escapes raw HTML itself -- `nh3.clean` there is defence-in-depth and removing it changes nothing observable; the TEMPLATE INTERPOLATION channel (session id, cwd, git branch, model, tool name, tool input) is guarded ONLY by Jinja2 `autoescape=True`, and turning that off puts live `<script>` into exports. The suite tested the first and not the second for a long time, which made the second look covered (`test_template_interpolation_escapes_transcript_content` now guards it). `render_markdown_text` sanitizes via `nh3.clean(raw, attributes={"code": {"class"}})` (the carve-out keeps fenced-code highlighting); Jinja2 runs `autoescape=True` and every `|safe` in the macros is safe ONLY because content is pre-sanitized (nh3) or pre-escaped (`html.escape`); every document ships a strict CSP built by `export/html.py::_build_csp` -- `default-src 'none'`, inline `<style>`/`<script>` blocks pinned by sha256, never `unsafe-inline`/`unsafe-hashes` (a hash covers a BLOCK; `style=`/`on*=` ATTRIBUTES stay forbidden everywhere -- `TestNoInlineConstructsForCsp` guards this). The hash must be computed over the exact emitted bytes: Jinja autoescape once corrupted an inline script AND its hash silently. Transcript content is untrusted input.
- `filter.js` is a Jinja2 TEMPLATE rendered via `_jinja_env`, not a static file; `static/transcript.js` is read as text and inlined. Both are hashed into the CSP.
- **A shared artifact is SCOPED, not scrubbed.** The warehouse spans every project on the machine, so anything handed to an agent or a person is generated for named projects only -- nothing else is in the file. Redaction is a filter you can forget to apply, and the silent-privacy-no-op has shipped three times here. `--private` stays as a secondary pass within the chosen scope, never as the boundary itself. Wiki and archive output is never git-tracked and lives under the home-anchored archive dir (`default_archive_output()`), never cwd.
- **Anything that sends transcript text off the machine is an ALLOWLIST that fails closed, verified by probes its author has not seen.** A blocklist's tests and scans come from its own patterns and cannot fail. Pass only plain words, short numbers and punctuation, and turn everything else into a category placeholder. Identity and credential checks refuse to run rather than skip, and a residue check that shares no patterns with the allowlist blocks what slips through. Scope (the owner picks sessions and fields) stays the boundary; the allowlist is the layer inside it. Build text for a third party with `include_thinking=False` whatever the flag says. Reference implementation and probes are untracked: `internal/jev_spike/stage2_ask.py`, `internal/egress_probes/probes.jsonl`.
- **The Antigravity lake reads an allowlist, and the data root holds OAuth tokens.** `<HOME>/.gemini` keeps `oauth_creds.json`, `jetski-standalone-oauth-token`, a browser profile and MCP config beside the transcripts. Every path the lake opens must match `parsers/antigravity/stores.py`'s anchored patterns, symlinks are recorded and never followed, and `tests/test_antigravity_lake.py::TestReadAllowlist` proves it with an audit hook against `chmod 000` decoys and a positive control. Add a file kind by widening the allowlist and the rules (then bump `LAKE_FORMAT_VERSION`; a pinned fingerprint test fails until you do), never by globbing. The allowlist keeps credential FILES out; it does not make the lake shareable, since transcripts can contain secrets agents printed. The Antigravity lake is an archive, not a re-derivable cache: do not delete it to "rebuild" the way a warehouse is rebuilt. Nothing it held may leave the current tree except into `_superseded/`: a unit rewrite carries forward the rows and tables the source dropped (`source_present = false`), and a source's `supersedes` hook snapshots the old unit when the new one is not a continuation. The first cut kept only whole units and an `idx` superset check, so a deleted `.db` beside a surviving brain dir wiped every step, a deleted conversation lost its only stated parent and depth (the summaries row), and a revert, which re-uses indices, overwrote the earlier branch. Test archive changes by rewriting a lake that already holds the rows, never only a first run.
- **Thinking text IS on disk for a minority of blocks -- treat it as real content.** The rate and its dated measurement are `docs/JSONL_CONTRACT.md` claim 5; its canary (`tests/test_jsonl_contract.py::TestThinkingTextIsAMinority`) prints current counts under `-s`. This bullet used to read "reasoning text is not on disk", an absolute about an unversioned upstream format, and it went false when Claude Code changed. State what ccutils DOES with a field, which a test can hold, never what the source contains. `has_thinking` counts blocks and says nothing about their text. Thinking text is excluded from `fact_messages.content_text` and, whatever the flag says, from the Tier 2 facet inputs (`tests/test_no_thinking_v15.py::TestTier2WithNoThinkingExcludesThinkingFromExtractor`). The one path in is `dim_session.last_assistant_message`, which stores it unless the build passes `--no-thinking` (`tests/test_guide.py::TestGuideOnReasoningText`). Whether to store reasoning deliberately is open in `docs/ROADMAP.md`.

## DuckDB / parsing idioms

- `json_extract(j, '$.p[*].f')::JSON[]` for lists; `LATERAL unnest(...)` when you need block + index; `json_type()` to gate string-vs-array `$.content`; `CAST(json_extract(...) AS VARCHAR)` for raw JSON (`json_extract_string` mangles arrays).
- DuckDB DML via `conn.execute(...)` returns the affected-row count as a one-row result -- that is how step counts stay real.
- `pydantic.alias_generators.to_camel` breaks on all-caps abbreviations (`sourceToolUseID` etc.) -- explicit `Field(alias=...)`; grep `alias=` in `parsers/models.py`.
- Stdlib `json` is the project convention; do not migrate to orjson.

## Workflow recipes

- **Before adding any new table, view or populator**: check it against the three rules in `docs/ETL_ARCHITECTURE.md` -- read staging not other facts; compute your own keys; an object earns existence by encoding something a consumer would get wrong, not by saving a JOIN. New work born conforming is work that stays off the migration list.
- **New fact table**: failing tests (DDL + lineage cols + behavior + idempotency) -> DDL with the standard lineage block -> `populate_fact_<x>` delegating to `lineage_upsert` (its projection MUST emit one row per declared `natural_key`; add the table to `NATURAL_KEYS`) -> wire into `run_v15_etl` in dependency order -> add to `_PROGRESS_TABLES` -> CHANGELOG + STAR_SCHEMA.md.
- **Removing a feature**: grep imports/`__all__`/CLI registrations/tests; delete; update CHANGELOG, README, `_PROGRESS_TABLES`; grep help text for stale counts.
- **Versioning**: version in `pyproject.toml`, sync with `CHANGELOG.md` (`[Unreleased]` promotes on release) AND `PARSER_VERSION` in `src/ccutils/_version.py` (it stamps every lineage row -- a stale value makes rows from different contracts indistinguishable); tag `v0.X.0`. Semver, no major bumps without permission.
